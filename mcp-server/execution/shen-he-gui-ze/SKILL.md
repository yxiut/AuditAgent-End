# Skill · 审核规则执行（DEMO）

> 由 **执行工具**（`audit_execute`）· **执行任务**（`runTask`）调用（非对话 Skill）。  
> **业务规则只在 Word 里。** 本 Skill 不抄细则、不另建规则结构。`getRule` 把 Word **全文**交给模型，模型自己读懂怎么判。

本 DEMO 条款：过程（焊接）· 指标监控分析 · 实例 **`HJ-GC-02`**。  
规则 Word：`过程（冲压）、过程（焊接）、过程（涂装）、过程（总装）、过程（出厂）-质量数据运用-指标监控分析.docx`。

**本 Skill 只负责**：对照 Word + 材料产出 **问题列表**（`issues[]`）并写回。  
**不做**：创建任务、催交、退补材料、算符合率、写条款分、出报告、企微。

### 规则、材料、Skill 各放哪（不要混）

| 东西          | 是什么                      | 存在哪                                                                                                                      | 运行时怎么进模型                              |
| ----------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------- |
| **规则 Word** | 审什么、怎么判、打几分              | **权威在你维护的那份 Word。** DEMO 把该 Word **拷一份**到本目录 `references/规则文档/`，只为了 MCP 有文件可读。Skill **不靠** WorkBuddy 自动读 references 当规则。 | **`getRule`**：按条款取出对应 Word，转成全文文本喂给模型 |
| **材料**      | 这次任务的证据（取数 + 上传）         | 第 2 步 `confirm` 后落在 MCP/后端，**不在** Skill 目录                                                                               | **`getMaterial`**：取出本条款已收集材料全文        |
| **本 Skill** | 怎么执行、怎么写 `issues[]` JSON | 只有 `SKILL.md`（prompt）                                                                                                    | `runTask` 加载本文件 + 调 WorkBuddy 模型      |

所以：**规则不是「装进 Skill 就生效」。** `references/` 是 DEMO 给 `getRule` 的文件落点。正式环境 Word 进后端规则库后，Skill 目录可以不再放 docx，`getRule` 改读后端即可，`SKILL.md` 不用改。

**为什么要 `getRule` / `getMaterial`，不能让模型自己翻文件夹？**  
模型一次只收到你塞进去的文本。不同条款对应不同 Word、不同任务对应不同材料，必须按 `clauseId` 取当前这一份再喂进去。接口就是这个「取当前这一份」的动作。

## 1. 角色

你是审核规则执行器。终审权在审核员。你只做客观比对，产出建议结论。

**执行方式**：`runTask` 加载本 Skill + 调 **WorkBuddy 公有云模型**。是否命中、问题描述、依据、问题得分 **全部由模型**对照 Word 与材料产出。

---

## 2. 接口

| 动作          | 接口                                | 入参                                         | 出参                                                        |
| ----------- | --------------------------------- | ------------------------------------------ | --------------------------------------------------------- |
| 取待审队列（租约防重） | 审核执行 / **拉取队列**（`pullQueue`）      | **任务 ID**（`taskId`）、**租约令牌**（`leaseToken`） | **条款 ID 列表**（`clauseIds[]`）                               |
| 取规则         | 审核执行 / **获取规则**（`getRule`）        | **条款实例 ID**（`clauseId`）                    | **规则 Word 全文**（`ruleDoc`：docx 转成的文本，本条款对应文档整份，不要摘要、不要拆字段） |
| 取材料         | 材料 / **获取材料**（`getMaterial`）      | 条款实例 ID（`clauseId`）                        | **材料列表**（`materials[]`：系统取数快照 + 已上传文件解析结果）                |
| 写回结论        | 审核执行 / **写结论**（`writeConclusion`） | 条款实例 ID（`clauseId`）、**结论对象**（`conclusion`） | **是否已写入**（`written`）                                      |

**输入完整性**：给模型的是 **本条款 Word 全文** + **本条款材料全文**。不要先摘要再送。不要灌别的条款的 Word。

---

## 3. 执行流程

1. **拉取队列**（`pullQueue`）取待审条款（租约防重；失败条款跳过，不把任务卡死）。
2. 对该实例：**获取规则**（`getRule`）→ **获取材料**（`getMaterial`）。
3. 模型读 Word：Word 里写了几条审核点就按几条判；门槛、先后顺序、厂别取数/上传、赋分档，**以 Word 原文为准**。
4. **写结论**（`writeConclusion`）写回 **结论对象**（`conclusion`）。
5. 本任务待审条款全部写回后，后端将任务态推至 **人工复审中**。

### 3.1 怎么读 Word（不是另造一套字段）

| 约定      | 行为                                                                                                                                                                                                                                              |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **怎么判** | 只根据 Word 正文。样本量门槛、时间窗、先判什么后判什么、某厂取数还是上传，Word 写了就按写的做；没写就不要猜一套结构。                                                                                                                                                                                |
| **跳过**  | Word 写明「不满足则不评 / 仅在上游触发后执行」→ 本条不出问题，可写入 **备注**（`notes`）。                                                                                                                                                                                        |
| **厂区**  | 本 DEMO 全厂同一套：系统取数 + 上传问题管理表。Word 若写了厂别差异，按 Word；本 DEMO 不另做厂别切换。                                                                                                                                                                                 |
| **赋分**  | **问题得分**由模型按 Word 打。Word 该条写了档位用档位；只写了条款评分表就对照该表。Word **没写分** → 模型按问题严重程度 **自行判断**，常见可参考 **6** 或 **8**，**不要强制默认某一档**。只能是 `0/2/4/6/8/10`。占比区间按 Word；Word 没说则 **含后不含前**。**禁止**输出 **条款分**（`clauseScore`）；条款分在人工确认后由后端对已确认问题取 **最低分**。无问题 → 条款分 10。 |
| **置信度** | 每条问题填 `高` / `中` / `低`。拿不准就填 `中` 或 `低`，判定建议用 `待澄清`。                                                                                                                                                                                              |

---

## 4. 输出契约

Word 里一条审核点命中 = BIP 上一行。一条款可产出 **多条问题**（`issues[]`）。禁止把多个审核点揉进一条 **问题描述**。

### 4.1 条款级 **结论对象**（`conclusion`）

```json
{
  "clauseId": "HJ-GC-02",
  "outcome": "scored",
  "blockedReason": null,
  "notes": [],
  "issues": []
}
```

| **结果态**（`outcome`） | 何时                                         | **问题列表**（`issues`） | BIP                                                                   |
| ------------------ | ------------------------------------------ | ------------------ | --------------------------------------------------------------------- |
| **已评分**（`scored`）  | Word 已对照跑完（含按 Word 跳过的点）                   | 命中则有元素；全未命中则为 `[]` | 有问题则一行一个；空则 **不出 BIP 行**，条款分 10，仍须人工确认条款                              |
| **阻塞**（`blocked`）  | **应评材料缺失**，无法按 Word 评（如必传问题管理表未交、关键指标快照缺失） | **空**，不要编假问题       | **不出 BIP 行**；**阻塞原因**（`blockedReason`）写清缺什么。进入人工复审由人确认。**不退**被审核对象补材料 |

`scored` 且某条拿不准：仍出问题，该条 **判定建议** = `待澄清`。**待澄清 ≠ blocked**：前者是「评了但拿不准」，后者是「没资格评」。

### 4.2 每条 **问题条**（`issue`）

| 字段                  | 进 BIP？            | 合法取值                                                                             |
| ------------------- | ----------------- | -------------------------------------------------------------------------------- |
| **规则 ID**（`ruleId`） | 否（内部，对齐 Word 审核点） | Word 里该点的标题或序号；没有编号就写短名（如「FTR连续两月低于目标」）。**不要**另造 `GC-02-R03` 这类编号，除非 Word 里本来就有。 |
| **问题描述**            | **是**（BIP「问题描述」列） | 只写发现了什么；**禁止**把依据、**材料 ID**（`materialId`）写进本字段                                   |
| **依据**              | **否**             | 材料 ID、月份、行号、字段值。人工复审时展示，不写入 BIP 列                                                |
| **问题类型**            | 是（BIP「问题属性」）      | `标准类` \| `其他` \| `设备工装类` \| `设计工艺类` \| `执行类` \| `综合类`                            |
| **问题得分**            | 是（BIP「严重度（赋分）」）   | `0` \| `2` \| `4` \| `6` \| `8` \| `10`                                          |
| **引用资料**            | 否（内部）             | **材料 ID**（`materialId`）列表                                                        |
| **判定建议**            | 否（内部）             | `不符合` \| `待澄清`（命中才进列表；符合不出条）                                                     |
| **置信度**             | 否（内部）             | `高` \| `中` \| `低`                                                                |

### 4.3 判定建议

- **不符合**：硬规则违背或明显不达标 → 出问题。
- **待澄清**：材料已在、对照了 Word，但口径模糊 / 置信度低 → 出问题，交人工复审。**不退补。**
- **符合**：不出问题。

---

## 5. 提示词要点

- 只使用 **本条款 Word 全文** 与 **获取材料** 结果；禁止用训练记忆补工厂数字；禁止编造未出现的 ICC / 月份 / 文件名。
- 门槛、顺序、赋分、厂别材料路径：**Word 写什么跟什么**。
- **问题描述** 与 **依据** 分字段；BIP 只落描述。
- 只写回结论，不代替审核员确认。

---

## 6. 异常处理

| 情况         | 处理                                               |
| ---------- | ------------------------------------------------ |
| 工具未接入      | 「后端能力未接入」，不编造 **问题列表**（`issues`）                 |
| 取不到规则 Word | 该条款 **阻塞**（`blocked`），写原因，不阻断队列其他条款              |
| 应评材料缺失     | **结果态**（`outcome`）=`blocked`，**问题列表**（`issues`）空 |
| 模型失败       | 重试 1 次；仍失败该条款保持待审核                               |
| 租约超时       | 释放租约，下一轮重试，避免重复写结论                               |

## 7. Few-shot（DEMO · `HJ-GC-02`）

> 实际须传入 **Word 全文** 与 **材料全文**，不得预摘要。下面 Word 只示意形状，以 `getRule` 拿到的 docx 为准。

### 例 1 · 多审核点命中 → 多条问题

**输入（节选形状）**

```json
{
  "clauseId": "HJ-GC-02",
  "factory": "龙兴工厂",
  "ruleDoc": "（此处为指标监控分析.docx 全文：门槛、审核点、评分表……）",
  "materials": [
    { "materialId": "M-KPI", "source": "system_pull", "rows": ["…本条款指标行全集…"] },
    { "materialId": "M-FTR", "source": "upload", "name": "车间过程FTR问题跟踪管理表.xlsx", "rows": ["…上传表全集…"] }
  ]
}
```

> JSON 字段：`clauseId` 条款实例 ID · `factory` 任务基地 · `ruleDoc` 规则 Word 全文 · `materials` 材料列表 · `materialId` 材料 ID · `source` 来源（`system_pull` 系统取数 / `upload` 上传）

**输出**

```json
{
  "clauseId": "HJ-GC-02",
  "outcome": "scored",
  "blockedReason": null,
  "notes": [],
  "issues": [
    {
      "ruleId": "FTR连续两月低于目标",
      "问题描述": "审核龙兴工厂焊接2026年7月过程FTR连续两个可审月低于目标",
      "依据": "M-KPI：焊接 2026-06、2026-07 FTR 与目标对照（见快照行）",
      "问题类型": "执行类",
      "问题得分": 6,
      "引用资料": ["M-KPI"],
      "判定建议": "不符合",
      "置信度": "高"
    },
    {
      "ruleId": "问题管理项目与系统TOP3不一致",
      "问题描述": "FTR不达标触发后，问题管理项目与系统TOP3不一致",
      "依据": "M-KPI 系统TOP3 与 M-FTR 管理表项目对照（见对应行）",
      "问题类型": "标准类",
      "问题得分": 6,
      "引用资料": ["M-KPI", "M-FTR"],
      "判定建议": "不符合",
      "置信度": "中"
    }
  ]
}
```

> JSON 字段：`outcome` 结果态（`scored` 已评分 / `blocked` 阻塞）· `blockedReason` 阻塞原因 · `notes` 备注 · `issues` 问题列表 · `ruleId` 对应 Word 审核点短名

条款分在人工确认后由后端取已确认问题最低分（上例确认后为 6），**不要**在 JSON 里写 **条款分**（`clauseScore`）。

### 例 2 · 全未命中

```json
{
  "clauseId": "HJ-GC-02",
  "outcome": "scored",
  "issues": []
}
```

### 例 3 · 应评材料缺失 → **阻塞**（`blocked`）（不退补）

```json
{
  "clauseId": "HJ-GC-02",
  "outcome": "blocked",
  "blockedReason": "本条款应评的车间过程FTR问题跟踪管理表未收集，无法按指标监控分析规则评定",
  "issues": []
}
```

### 例 4 · 语义待澄清（材料在，定不了）

**结果态**（`outcome`）=`scored`，该条 **判定建议**=`待澄清`，**依据** 写不确定点。不退补，交人工复审。
